# 03 — Sprint Planning & Backlog

## Six-Sprint Roadmap

| Sprint | Focus | Key Deliverables | Exit Criteria |
|---|---|---|---|
| 1 | Discovery & alignment | Requirements, personas, acceptance criteria | Scope and priority baseline approved |
| 2 | UX / UI redesign | Checkout wireframes and high-fidelity designs | Design approval complete |
| 3 | Cart experience | Cart updates, validation, analytics events | Stories accepted; QA-ready build |
| 4 | Checkout experience | Checkout flow, error states, accessibility fixes | End-to-end flow passes QA |
| 5 | UAT & hardening | UAT, defect resolution, release checklist | No critical defects; UAT sign-off |
| 6 | Launch & measurement | Release, monitoring, KPI review | Launch complete and metrics baseline captured |

## Prioritized Backlog

| ID | User Story | Priority | Acceptance Criteria |
|---|---|---|---|
| US-01 | As a shopper, I want a clear cart summary so I can verify my order before checkout. | Must | Totals, quantities, and edit/remove actions are visible and testable. |
| US-02 | As a shopper, I want checkout steps to be clear so I know where I am in the process. | Must | Progress indicator and validation states are present. |
| US-03 | As a shopper, I want useful error messages so I can recover from invalid inputs. | Must | Errors identify the field and corrective action. |
| US-04 | As a product owner, I want checkout events tracked so I can measure funnel performance. | Must | Required events fire with agreed parameters. |
| US-05 | As a shopper, I want accessible controls so I can complete checkout reliably. | Should | Keyboard/focus, labels, contrast, and screen-reader requirements are tested. |
| US-06 | As a PM, I want release criteria documented so launch decisions are objective. | Should | Checklist includes QA, UAT, analytics, defects, and approvals. |

## Definition of Done
A story is complete when acceptance criteria are met, peer review is complete, QA evidence is recorded, analytics requirements are validated where applicable, and the product owner accepts the result.

## Sprint Ceremonies
- Sprint planning
- Daily stand-up
- Backlog refinement
- Sprint review/demo
- Retrospective

## Delivery Controls
Velocity is used as a planning signal rather than a performance target. Scope changes are evaluated against timeline, risk, dependencies, and the cart-abandonment outcome.
